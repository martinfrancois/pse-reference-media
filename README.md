# pse-reference-media

Short, silent excerpts of openly licensed video, each with its licence, credit, source and an
exact technical description. The clips are ordinary footage that a checker for photosensitive
epilepsy guidelines (Ofcom, ITU-R BT.1702, WCAG 2.3.1 and similar) should pass. They cover fast
cuts, pans, grain, water, foliage, text and fades, plus a range of frame rates, frame sizes,
containers and pixel formats that such a checker has to read.

None of the clips flashes. A checker that flags one of them has a false positive.

[`manifest.json`](manifest.json) is the machine-readable record of every clip, and
[`manifest.schema.json`](manifest.schema.json) documents its fields.

## Clips

`scripts/render_readme.py` generates the table from `manifest.json`. The credit column gives
the attribution in the form the rights holder asks for, the licence, the source and what was
changed.

## Licences

The scripts and documentation are under the Apache License 2.0 (see [`LICENSE`](LICENSE)). The
Apache License does not cover the clips.

Each clip keeps the licence of the work it was cut from, as listed in the table and in
`manifest.json`. When you share a clip:

- **CC BY.** Give the credit from the table, link the licence and say what was changed. The
  table already states the changes made here; add your own if you change the clip further.
- **CC BY-SA 4.0** (`car-park-portrait-25fps.mpg` and `simple-animated-clock.webp`). The same
  credit rules apply. If you share a modified version, such as a re-encode or a crop, it has to be
  under CC BY-SA 4.0 or a compatible licence, and you have to say what you changed.
- **Public domain.** No credit is required, but the table gives one anyway. NASA's
  [media guidelines](https://www.nasa.gov/nasa-brand-center/images-and-media/) ask for credit,
  exclude the NASA insignia and logotype, and say that using an image of an identifiable person
  for commercial purposes may need that person's permission. That applies to the astronaut in
  `iss-lab-interlaced-sd.mpg`.

`arctic-ice-graphics-50fps.webm` carries a faint ZDF watermark in one corner, as ZDF published
it. CC BY 4.0 does not cover trademarks, so the clip gives no right to use the ZDF logo.

The Tears of Steel soundtrack is under CC BY-ND 3.0
([copyright.txt](https://download.blender.org/demo/movies/ToS/copyright.txt)). The clips contain
no audio, so that licence does not apply to them.

## Verify the clips

[`scripts/verify.py`](scripts/verify.py) checks that `manifest.json` follows the schema and that
every file in `clips/` matches its entry: size, SHA3-256, no audio or other non-video streams, the
8 MB limit per clip, the 120 MB limit in total, and every ffprobe fact. CI runs it on every pull
request and on `main`.

```sh
mise install
mise exec -- python -m venv .venv
.venv/bin/python -m pip install --require-hashes --no-deps -r requirements.txt
mise exec -- .venv/bin/python scripts/verify.py
mise exec -- .venv/bin/python scripts/render_readme.py --check
```

[`mise.toml`](mise.toml) installs Python 3.13 and the conda-forge build of ffmpeg 8.1.2, which
recorded the facts. `requirements.txt` pins jsonschema and its dependencies with hashes; its header
holds the `uv pip compile` command that refreshes it. Set `FFPROBE` or `FFMPEG` to use another
build. Another version of ffprobe can report some facts differently; `verify.py` prints a note when
the versions differ.

## Re-create the clips from their sources

[`scripts/recreate.py`](scripts/recreate.py) downloads each source, checks its size and
SHA3-256, runs the recorded ffmpeg command and compares the result with the file in `clips/`.

```sh
mise exec -- .venv/bin/python scripts/recreate.py --work-dir /path/to/work
mise exec -- .venv/bin/python scripts/recreate.py --work-dir /path/to/work --clip sea-waves-pier.webm
```

A full run downloads 17 files, about 2.4 GB, and extracts another 2 GB from zip archives. The
interlaced ISS clip reads its 12 GB source over HTTP and fetches only the part it needs, so that
source has no SHA3-256 in the manifest, only the SHA-1 and MD5 that archive.org publishes.

The output is byte-identical only with the ffmpeg build named in `manifest.json`. ffmpeg 8.1.3,
for example, writes a different MP4 and QuickTime header for the same stream copy, so the digests
differ even though the video data is the same. I cut the clips with 8.1.2 because it is the
newest 8.1 release that `mise` can install from conda-forge, which goes from 8.1.2 straight to 9.0.

## How the clips were made

Most clips are stream copies: ffmpeg starts at a keyframe and copies the compressed video without
decoding it, so every frame is the source frame. The commands use `-copypriorss 0` so that no
frames before the start point leak in, and `-fflags +bitexact` with `-map_metadata -1` so that
the output does not depend on the date or the encoder string.

Two clips are re-encoded, and `manifest.json` records the measured difference for both:

- `iss-lab-interlaced-sd.mpg` comes from a D-10 recording: intra-only MPEG-2 4:2:2 at 30 Mbit/s.
  A stream copy of 4 seconds would be about 15 MB, so it is re-encoded to interlaced MPEG-2 4:2:2
  with the same frame size, field order, frame rate, sample aspect ratio and transfer tag.
- `lucy-dinkinesh-approach.avif` is a lossless AV1 encode of the MP4 source. The only openly
  licensed animated AVIF I found, a libavif test file, switches between full-screen colours 30
  times a second.

The GIF, APNG and WebP files are the unchanged source files, so their lengths are the sources'
lengths: the APNG loop is 1.5 seconds and the WebP 11.5 seconds. The WebP is a small clock
animation because the larger WebP candidate I found was 36.8 MB.

I added or corrected no colour tags. Where a source has no colour tags, the clip has none either,
and the manifest records them as `null`.

Before a clip went in, I looked at a contact sheet of its frames and checked the mean luma of
every frame for sudden jumps. These checks are not part of this repository.

## Add a clip

1. Find a source under CC0, public domain, CC BY, CC BY-SA or a BSD licence. Read the rights
   holder's licence statement yourself. Leave out anything under a NonCommercial or NoDerivatives
   licence, and anything whose statements disagree.
2. Leave out flashing content: strobes, lightning, gunfire, fireworks, emergency lights and
   anything with rapid changes in brightness or saturated red. Leave out title cards with logos.
3. Cut the clip without audio, 4 to 10 seconds long and at most 8 MB, with the ffmpeg build from
   `mise.toml`. Use a stream copy from a keyframe where you can; otherwise re-encode at the same
   frame size, frame rate, bit depth and colour tags, and measure the difference.
4. Add an entry to `manifest.json` that follows `manifest.schema.json`. Print the file-derived
   fields with `mise exec -- .venv/bin/python scripts/clipfacts.py clips/<name>`.
5. Run `scripts/render_readme.py` to update the table, then `scripts/verify.py`.

## What is not here, and why

- **Audio.** Checkers for photosensitive epilepsy look at the picture only, and soundtracks often
  carry a different licence.
- **Flashing content.** This set is the ordinary footage that should pass. I left out strobes,
  lightning, gunfire, fireworks and emergency lights on purpose, and excerpts where the luma check
  found sudden brightness changes, such as the splice flares in the 1947 film.
- **HDR.** No HDR source fits the rules today:
  - [SVT Open Content](https://svt.github.io/content) has PQ-coded HDR sequences under CC BY 4.0,
    but the water_flyover source alone is 14.8 GB, and an excerpt at visually lossless quality
    would be far over 8 MB.
  - Netflix's Sol Levante (37 GB) and Nocturne (93 GB) are too large, and Netflix's own
    [README](https://s3.amazonaws.com/download.opencontent.netflix.com/aom_test_materials/README.txt)
    lists both as CC BY-NC-ND 4.0.
  - [20240707 hummingbird wm 1 hlg 05.webm](https://commons.wikimedia.org/wiki/File:20240707_hummingbird_wm_1_hlg_05.webm)
    (CC BY-SA 4.0) is 13.8 MB, over the limit, and I have not probed it.
  - [Eclipse (4K HDR).webm](https://commons.wikimedia.org/wiki/File:Eclipse_(4K_HDR).webm)
    is marked CC BY 4.0 but its licence review on Wikimedia Commons is still pending.
  - Blender Studio's [Singularity](https://studio.blender.org/projects/singularity/pages/licensing/)
    was made in HDR, but I found no public HDR download.
- **Copyrighted footage under restrictive licences.** I used only licences that allow sharing
  excerpts. That rules out the Netflix Open Content titles other than Cosmos Laundromat:
  Netflix lists Sparks, Meridian, Sol Levante and Nocturne as CC BY-NC-ND 4.0, and the
  [El Fuente](https://s3.amazonaws.com/download.opencontent.netflix.com/Netflix_test_conditions/ElFuente_copyright.txt)
  and [Chimera](https://s3.amazonaws.com/download.opencontent.netflix.com/Netflix_test_conditions/Chimera_copyright.txt)
  statements say the same.

Some cases are still missing: live action at 50 fps, frame rates of 100 and 120 fps, variable
frame rate, and a 10-bit SDR clip with correct colour tags.
